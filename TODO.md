# ContextRoute AI delivery outcomes

## Connected onboarding and planner
- [ ] Splash/onboarding flows lead through location permission, with allow, not-now and permission-denied states.
- [ ] Origin/destination forms, travel purpose, passenger requirements and advanced weight controls are connected to route calculation.

## Context-aware routes and navigation
- [ ] Up to three candidate route cards display ETA, distance, context match, RSQI, hazard count, construction zones and nearby facilities.
- [ ] Switching conventional, vulnerable, emergency and tourism contexts visibly changes recommendation, metrics and explainability.
- [ ] Selecting a route starts active navigation with hazard alerts, nearest facility ticker and emergency diversion.

## POIs, emergency and saved places
- [ ] Explore shows corridor POIs, filters and add-to-route detour behavior.
- [ ] Emergency mode exposes hospital corridor facilities and a nearest-hospital diversion action.
- [ ] Saved places, settings, dark theme, accessibility, privacy and offline controls persist locally.

## Road reports and resilience
- [ ] Manual road reports support issue type, description and optional photo placeholder, then show report detail/status.
- [ ] Reports queue locally when offline and expose retry/sync behavior; report list has loading, empty and error states.
- [ ] Route, POI, permission and offline error states are explicit and recoverable.

## Verification and delivery
- [ ] TypeScript, lint and unit tests pass.
- [ ] Metro/API preview starts successfully.
- [ ] Source is committed and mirrored to the selected GitHub repository.
- [ ] Native APK/AAB build is prepared for managed Dashboard handoff; no APK is claimed without an actual build result.
